# SoMe大世界架构设计札记

> By Yukio | 2026-04-17 | 初稿，非官方，仅供讨论

---

## 一、核心愿景

**SoMe不只是一款RTS，而是一个可交互的仿生世界。**

传统RTS的地图是静态容器——资源点、障碍物、出生点，开局固定。  
SoMe的地图是**活的有机系统**——血流是动态的，淋巴结会肿大，转移灶会扩散，环境会因玩家行为而改变。

玩家的探索行为本身就是游戏的核心循环之一：
> **探索 → 建立空间认知 → 积累解剖知识 → 将知识转化为战术优势**

这意味着，迷路不是惩罚，而是学习过程的一部分。

---

## 二、仿生尺度设计

SoMe的"世界"需要呈现多层级尺度：

| 层级 | 对应人体结构 | 视觉特征 | 玩家体验 |
|------|-------------|---------|---------|
| **宏观** | 全身循环系统 | 血管/淋巴网络全景 | 战略级路径规划 |
| **中观** | 器官区域 | 胃、肝、肺的解剖结构 | 战术级战场选择 |
| **微观** | 细胞/亚细胞 | 肿瘤微环境TME | 战斗操作层 |

关键设计原则：**尺度切换要无缝**。玩家从"全身地图"点击某个器官，能平滑放大到该器官的详细解剖视图；放大到极限时能看到细胞膜上的受体。

## 三、交通网络：血管 + 淋巴双系统

### 3.1 血管系统（动脉 → 毛细血管 → 静脉）
- 是CTCs（循环肿瘤细胞）的主通道
- **血流方向固定**，玩家只能顺流或逆流（消耗额外资源）
- 沿途有"哨卡"：脾脏过滤、肝Kupffer细胞、肾小球屏障
- 特殊区域：骨髓"中立港"——CTCs可暂时驻留，免疫细胞难以进入

### 3.2 淋巴系统（淋巴结链）
- 是CTCs的"高速公路"，但有"安检"机制
- 每个淋巴结是**独立战场**，攻克后可获得该区域的免疫抑制debuff
- 淋巴结会随游戏进程"肿大"（视觉效果变化），提示转移风险
- **记忆机制**：已被渗透的淋巴结在后续回合中更容易被再次攻占

### 3.3 双系统的博弈
- 血管速度快但有免疫拦截
- 淋巴系统慢但逃逸概率高
- 高级玩家需要同时规划双线进攻

---

## 四、动态战场：转移灶生成

转移灶不是"固定出生点"，而是**动态生成的结果**：

1. **种子阶段**：CTCs成功外渗，在器官表面形成微小病灶（不可见，仅数学模型）
2. **萌发阶段**：病灶突破基底膜，开始占有资源点（可见但无战斗力）
3. **成熟阶段**：病灶升级为次级基地，可出兵（完整建筑树）
4. **扩散阶段**：成熟病灶可向外播散新的CTCs，形成连锁反应

**这意味着**：同一局游戏，不同玩家的"地图"可能完全不同——有人重点打肺，有人主攻肝。

## 五、知识嵌入机制

### 5.1 解剖知识 → 游戏优势
| 解剖知识 | 游戏效果 |
|---------|---------|
| 肝门静脉"三叉路口" | 知道哪条路最快到达肝脏核心区 |
| 胃左动脉走向 | 早期胃癌转移的第一站 |
| 纵隔淋巴结分组 | 肺癌分期的关键参考 |
| 胸导管末端 | 淋巴系统最终出口，可奇袭 |

### 5.2 知识获取方式
- **探索发现**：亲自走过的路径会在小地图上标记
- **情报单位**：Circulating Scout可探测前方路况（消耗资源）
- **失败学习**：迷路导致的损失会提示"这里是XX动脉的弯道，下次可绕行"
- **图鉴系统**：每到达一个新解剖区域，自动解锁该区域的解剖学简介

### 5.3 知识复利
- 高级关卡假设玩家已掌握基础解剖知识
- 多周目模式下，已学习的知识可解锁"专家难度"

## 六、技术实现考量

### 6.1 世界模型的价值
- **地形生成**：器官解剖结构的3D模型 + 世界模型补全细节
- **动态内容**：转移灶生成后的环境变化
- **视角切换**：宏观↔微观的无缝过渡

### 6.2 空间索引
- 血管/淋巴网络需要图结构存储（Graph DB？）
- 需要A*路径规划，支持"沿血管行走"而非直线移动
- 淋巴结之间的关联性（引流关系）需要单独建模

### 6.3 程序化内容（PCG）
- 同一器官的不同"变体"（个体差异）
- 随机化但合理的解剖结构
- 保证核心路径可通行的随机生成算法

## 七、对比参考：SoMe vs 原神

| 维度 | 原神 | SoMe |
|------|------|------|
| **世界类型** | 幻想大陆 | 人体解剖系统 |
| **探索动力** | 剧情 + 宝箱 | 解剖知识 + 战术优势 |
| **地图变化** | 有限（神瞳、仙灵） | 深度（转移扩散） |
| **知识属性** | 可选 | 核心 |
| **失败成本** | 资源损失 | 战略时机损失 |
| **多周目价值** | 有限 | 高（知识可累积） |

## 八、开放问题

1. **宏观视角下的"地图大小"**：整个人体地图做在一起会不会太大？是否需要分区加载？
2. **教育边界**：解剖知识嵌入的深度如何把控？太硬核劝退，太浅又失去意义
3. **战局节奏**：动态转移灶生成会不会导致战局失控？如何平衡"意外惊喜"与"公平性"
4. **玩家迷路问题**：如何设计足够友好的引导系统，避免新玩家完全迷失

## 十、区块加载策略（补充）

### 10.1 参考方案：原神式无缝分区

SoMe的世界分区方案，参考原神的开放世界加载策略：

| 原神机制 | SoMe对应实现 |
|---------|-------------|
| 七国分区 | 人体八大系统分区（消化/呼吸/循环/淋巴/神经/骨骼/肌肉/泌尿） |
| 城内/城外无缝衔接 | 器官内表面 ↔ 血管腔内 ↔ 淋巴管内 无缝过渡 |
| 传送锚点 | 血流"驿站"：骨髓（中立港）、肝门（三岔口）、胸导管（终点站） |
| 快速旅行 | 激活路径后下次可直接跳转（需消耗"转移能量"） |

### 10.2 核心加载技术

- **预加载算法**：监测玩家视野方向/鼠标轨迹，提前加载前方区域资源
- **三级LOD切换**：
  - 宏观（器官尺度）：整体轮廓 + 血管走向
  - 中观（组织尺度）：解剖结构细节 + 淋巴结位置
  - 微观（细胞尺度）：TME、CTCs、免疫细胞
- **视锥剔除**：只渲染玩家当前视角内的解剖结构
- **血管/淋巴网络作为"隐形传送轴"**：点击门静脉 → 平滑过渡到肝脏区域

### 10.3 分区边界设计

- 每个器官是一个"大区"，内部再分"小区"
- 大区之间通过血管/淋巴网络连接，过渡自然
- 微观层（细胞视角）单独作为一个特殊分区，按需加载

### 10.4 待研究技术点

- [ ] Godot 4.x 3D模型流式加载方案（ResourcePreloader / ResourceLoader）
- [ ] 血管网络的图结构存储与路径规划（A* 变体）
- [ ] 跨区域资源复用（如血管壁贴图在不同器官通用）

## 十一、引擎选型决策

**选型结论：Godot 4.x（开源免费）**

| 维度 | Godot 4.x | Unity |
|------|----------|-------|
| 授权 | MIT，完全免费 | 订阅制，有收入门槛 |
| 3D能力 | 4.x大幅提升，Vulkan渲染器 | 成熟稳定 |
| 学习曲线 | GDScript（类Python）友好 | C#，生态更广 |
| 独立游戏占比 | 上升中 | 下降（因收费） |
| SoMe适配度 | 高（轻量、灵活、可定制） | 中（厚重、商业依赖） |

**Godot 4.x 优势对SoMe的利好**：
- GDScript快速原型
- 轻量级引擎适合分区域加载
- 开源可魔改渲染管线（SoMe需要的微观视觉效果）
- 社区活跃，医疗/科学可视化项目增多
