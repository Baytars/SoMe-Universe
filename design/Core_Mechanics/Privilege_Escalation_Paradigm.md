# SoMe 核心机制：提权式成长范式

> **文档状态**：v1.0 | **创建日期**：2026-07-22 | **关联文档**：`Carbon_Based_Cyberspace.md`、`Notch_Lock_System.md`、`Opening_Sequence_Somnambule.md`

---

## 1. 范式定义

### 1.1 核心命题

传统RPG的成长是**数值上升（Power Escalation）**：起点是完整的人，终点是超人。玩家追求"更强"。

SoMe的成长是**权限恢复（Privilege Restoration）**：起点是被锁死的人，终点是恢复正常人。玩家追求"正常"。

```
传统RPG：  完整的人 ──(+50 ATK)──> 超人
SoMe：     被锁死的人 ──(unlock permission)──> 正常人
```

### 1.2 Access Fantasy 取代 Power Fantasy

在别的游戏里，能动手指、能说话、能走路是默认起点。
在SoMe里，这些是**earned的胜利**。

- 传统游戏给玩家的爽感："我变强了"
- SoMe给玩家的爽感："我终于能影响这个系统了"

每一级提升不是数字变大，是对自身系统的理解加深一层。玩家不是在"升级"，是在"夺回"。

### 1.3 设计含义

| 维度 | 传统RPG | SoMe |
|---|---|---|
| 成长方向 | 向上突破 | 向内恢复 |
| 数值模型 | 线性/指数增长 | 权限位解锁 |
| 终点定义 | 最强 | 正常 |
| 玩家体验 | Power Fantasy | Access Fantasy |
| 失败惩罚 | 数值回退 | 权限被重新锁定 |
| 成就感来源 | "我比敌人强" | "我重新拥有了自己的身体" |

## 2. 信号通路 → IPC协议映射

### 2.1 修正记录

**此前错误映射**：Notch = root restore command（将信号通路映射为特定命令）

**修正原因**：信号通路没有细胞特异性。同一条Notch信号在上皮抑癌、在T细胞致癌——命令是单一确定性的，但信号通路不是。

**正确映射**：信号通路 = IPC协议规范

### 2.2 完整映射表

| 生物学概念 | 碳基赛博空间概念 | 说明 |
|---|---|---|
| 信号通路（Notch/Wnt/MAPK） | **IPC协议规范** | 定义消息怎么传，不定义收到后做什么 |
| 配体（ligand，如DLL4） | **消息载荷（message payload）** | DLL4→Notch就像一条带类型的event |
| 受体（receptor，如Notch） | **消息订阅端口（subscription port）** | 每个进程可以监听也可以不监听 |
| 信号转导级联 | **中间件管线（middleware pipeline）** | 信号在传递中被转换、放大、过滤 |
| 转录因子激活 | **handler写入系统状态** | 最终行为=handler实现 |
| 细胞类型特异性响应 | **进程各自的handler实现** | 同一条消息，不同进程干不同的事 |

### 2.3 核心洞察：Lockdown Loop在Handler层，不在协议层

```
海葵 v0.1 (Nematostella vectensis)
  └── Notch handler 有 root 权限
      └── 收到信号 → 重建整个生物体

人类 v2.0 (Homo sapiens)
  └── Notch handler 被加了访问控制
      └── 同样的信号进来 → handler 只能做被允许的操作
          └── 在上皮：抑制增殖（抑癌）
          └── 在T细胞：促进增殖（致癌）
```

**协议从v0.1到v2.0没变过。变的是handler的权限策略。**

- 海葵的handler是root级别：收到Notch信号就能启动全身再生
- 人类的handler被加了访问控制：防癌代价——细胞不能随意可塑
- Umin要找的漏洞：handler权限提升路径（不是破解通信协议）

## 3. 8级康复弧线 = 8级权限提升

| 阶段 | 临床状态 | 碳基赛博空间状态 | 权限等级 | 玩家体验 |
|---|---|---|---|---|
| 1 | 闭锁综合征 | 意识在线，所有输出通道断开 | `read-only` | 能看能想，不能动 |
| 2 | Eiko建立BCI | 第一个IPC通道打开 | `write to 1 port` | 终于能"说话"了——通过Eiko |
| 3 | 眼球运动恢复 | 单个子系统获得写入权 | `limited write` | 直接控制身体的一部分 |
| 4 | 指挥Eiko巡逻 | 获得防御系统的有限调用权 | `sudo (scoped)` | 能调度"外部程序" |
| 5 | 修复首个脑区 | 对应模块恢复在线 | `module admin` | 夺回一个"部门"的控制权 |
| 6 | 多系统协调恢复 | 跨模块调度能力 | `cross-module dispatch` | 能协调多个子系统 |
| 7 | 高级功能恢复 | 执行层权限接近完整 | `near-root` | 几乎正常，但还有最后的安全限制 |
| 8 | 完全康复 | 身体所有权归还 | `root restored` | 正常人——这就是终点 |

### 3.1 每一级提升的设计原则

1. **不是数值跳跃，是认知跃迁**：每解锁一层权限，玩家对自身系统的理解加深一层
2. **权限即能力**：玩家获得的不是"+50攻击力"，而是"你现在可以影响这个系统了"
3. **可回退**：权限不是永久获得的。治疗有反复，权限可以被重新锁定（疾病进展/并发症）
4. **权限有边界**：每级权限都有scope。Level 4的sudo只在特定范围内有效，不是全局root

## 4. 玩家与Umin：同一技术的镜像

### 4.1 镜像关系

```
玩家（Somnambule）           Umin（The Unseen Crown）
    │                              │
    │  同一技术：privilege          │
    │  escalation（提权）           │
    │                              │
    ▼                              ▼
  意图：restore                  意图：exploit
  （恢复被锁的权限）              （利用漏洞夺取控制）
    │                              │
    ▼                              ▼
  终点：root restored            终点：root hijacked
  （恢复正常人）                  （细胞被感染转化）
```

### 4.2 镜像实例

| 技术 | 玩家用法（restore） | Umin用法（exploit） |
|---|---|---|
| handler权限提升 | 解锁Notch→神经再生 | 解锁Notch→细胞可塑→感染转化 |
| 海葵v0.1源码研究 | 理解正常再生机制→治疗 | 找lockdown漏洞→武器化 |
| 信号通路劫持 | 重新建立断开的IPC通道 | 劫持信任链→木马入侵 |
| 细胞可塑性诱导 | 让梗死区神经元重编程 | 让正常细胞去分化→肿瘤转化 |

### 4.3 叙事含义

- Umin不是"绝对邪恶的反派"，而是**同一技术的镜像使用者**
- 玩家与Umin的冲突不是"正义vs邪恶"，是"restore vs exploit"的意图对立
- 最深刻的抉择：玩家需要用Umin的研究成果来治疗自己——**敌人的exploit是你的restore manual**
- 伦理困境：解锁=再生可能，但也是癌症风险；而且这是Umin的技术，能接受吗？

## 5. 用药即提权：药物系统的游戏化

### 5.1 药物 = 权限调用工具

在SoMe的碳基赛博空间框架下，药物不是"武器"（用来攻击疾病），而是**权限调用工具**：

| 药物类型 | 赛博空间类比 | 机制 |
|---|---|---|
| 激动剂（agonist） | `sudo` 命令 | 以高权限身份调用目标handler执行写操作 |
| 拮抗剂（antagonist） | `chmod` 命令 | 修改目标handler的权限位，撤销写权限 |
| 别构调节剂 | 环境变量修改 | 不直接操作handler，改变handler的运行上下文 |
| 靶向药物 | 特定UID的sudo | 只对特定细胞类型的handler生效 |
| 联合用药 | 管道命令（pipeline） | 多个权限操作组合执行 |

### 5.2 核心隐喻

**用药不是"与疾病作战"，而是"调用一个有高权限的用户对目标系统进行写操作"。**

- 药物分子 = 携带特定权限凭证的调用请求
- 受体 = 目标系统的访问端口
- 信号转导 = 权限验证中间件管线
- 细胞类型特异性响应 = 不同进程的handler实现差异
- 副作用 = 权限溢出（sudo作用域太大，影响了不该影响的进程）

### 5.3 游戏机制含义

- 玩家选择药物 = 选择"用什么权限身份去操作系统"
- 同一药物在不同细胞类型中效果不同 = 同一sudo命令在不同进程中有不同handler
- 药物耐药性 = 目标系统更新了权限策略（handler被重新配置）
- 联合用药策略 = 设计权限操作管线，避免权限冲突

## 6. 设计哲学总结

SoMe用**权限模型**替代**数值模型**，这意味着：

1. **成长不是积累，是恢复**。玩家不是在变强，是在变完整。
2. **疾病不是敌人，是锁**。Umin不是要打败的boss，是同一技术的镜像使用者。
3. **治疗不是战争，是黑客行为**。用药不是攻击，是提权调用。
4. **终点不是最强，是正常**。能动手指、能说话——这些在别的游戏里是默认起点，在SoMe里是earned的胜利。

这个范式如果成立，SoMe是用权限模型替代数值模型的全新成长体系。
